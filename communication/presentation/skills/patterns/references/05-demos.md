# Demonstrations and Code

_When and how to show live/recorded demos and code without the demo failing you._

**Live Demo** (P) — Run tool/code live in real time to gain credibility; can become performance art. How: ad-lib fluently while keeping lively banter; firm agenda + goals, say no to derailing requests; deep expertise, heavy practice; pre-build intermediate snapshots to restart from; optionally open with a few live examples then switch to Lipsync. Avoid: high risk, ROI rarely worth it; unrecoverable failure harms reputation; advanced presenters only — else degrades into Dead Demo. See: Dead Demo, Lipsync, Carnegie Hall.
**Dead Demo** (AP) — Lengthy live demo used as time-sink filler for thin/dull content or ego, aspiring to Live Demo but falling short. Fix: build a real presentation; use Lipsync, Traveling Highlights, or Emergence — more material (live covers ~60%), more detail, less stress. See: Live Demo, Lipsync.
**Lipsync** (P) — Pre-record tool interaction as video, play back during talk instead of demoing live — cuts stress/errors, lets you narrate with full focus and read heads-up notes. How: screen-capture full-screen, embed in slide, overlay animations; edit for time, pause/replay, capture rare error states in the lab; turn off notifications, hide desktop lint, mask glitches with borderless white box; save tagged checkpoints/version-control snapshots so you can branch to live on audience request. Avoid: don't fake it as live — credibility dies if caught; loses live improvisation. See: Dead Demo, Live Demo, Context Keeper, Live on Tape.
**Live on Tape** (P) — Video-record your entire talk as if live and deliver electronically when travel/time/budget blocks onsite delivery; higher-fidelity and wider reach than a flat PDF. How: phone-stand + HD phone (simplest); or composite desktop capture + webcam picture-in-picture via screencast app; hide desktop distractions, use solid wallpaper (aids compression). Avoid: harder with physical props or 3D/interactive media; manage expectations if audience wanted you in person. See: Lipsync, Live Demo.
**Emergence** (P) — Gradually reveal pieces/details of a big thing (diagram, tool, source, formula) via motion, transitions, and highlights instead of dumping it all at once. How: obscure parts with borderless white boxes / Keynote magic move, remove them piecewise while narrating each. Avoid: for Slideuments, pre-set obscuring boxes to 0% opacity then add short pre-entrance animations to 100% so final print state shows the full slide. See: Traveling Highlights.
**Crawling Code** (P) — Reveal one portion of a long text/code block at a time (on cue, not continuous), scrolling bottom-to-top; out-of-focus lines shaded, surrounding lines kept for peripheral context, creating illusion of a larger canvas. How: keep text in one field at ~22pt overflowing the slide, highlight/box target segments (group boxes with text), path-animate the block upward; use back-navigation to revisit segments. Avoid: significant setup time; predetermined order limits Q&A spelunking — keep text in an editor for free-form questions. See: Crawling Credits, Traveling Highlights.
**Traveling Highlights** (P) — Move a highlight across parts of a slide via transitions to focus attention while leaving the rest visible for context; raises info density. How: use built-in highlighting or add-on (e.g. OmniDazzle); screenshot real tool output (IDE/spreadsheet) full-screen not retyped text; overlay recaptured highlighted region and dissolve-in, or zoom+opacity to "grow" each element while rest dims; use Analog Noise to mark added elements; test animations on target hardware (limited on iPad Keynote). Avoid: for units too large for one slide use Crawling Code. See: Crawling Code, Emergence, Context Keeper.
