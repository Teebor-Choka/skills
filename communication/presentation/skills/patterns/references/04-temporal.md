# Patterns Over Time

_Controlling how content reveals over time and how the audience tracks progress._

**Context Keeper** (P) — Reveal talk's structure via presentation device (animation/transition), temporally or by subject. How: many implementations — different bg color per section, Keynote magic move (shared elements migrate between slides, never leaving screen), recurring anchor element. PowerPoint lacks magic move; fake via symmetrical exit/entrance animations (e.g. wipe out then wipe in). Avoid: recurring element becoming Floodmark — fade its opacity on later slides. See: Breadcrumbs, Bookends, Intermezzi, Backtracking, Narrative Arc.
**Bookends** (P) — Similar/identical slides at start AND end wrapping the WHOLE talk; advertise presenter + contact info, entice/repel passersby to self-select audience, signal talk is over. How: opening slide = name, title, email, Twitter, blog, company, license; closing adds "Questions?", slides-download URL, feedback URL. Consumes no talk time. See: Preroll, Crawling Credits, Intermezzi (Bookends wrap whole talk, Intermezzi wrap sections), Crucible.
**Breadcrumbs** (P) — Agenda trail; checkpoint slides at junctures showing where you are in overall structure. How: replicate agenda slide throughout, highlight upcoming section or dim completed (à la Charred Trail); or mind map with highlight box / reduced opacity on non-current items. Avoid: real-time progress bars (metapresentation → Going Meta); over-reliance signals poor organization. See: Context Keeper (specific implementation of), Bookends.
**Intermezzi** (P) — Transitional buffer slides wrapping SECTIONS; color change, thematic shift, or outline intro signaling start/end of a logical part. How: opening list of items to cover, closing list just covered inviting questions, representative picture, or loaded question; tie to Unifying Visual Theme. Best for talks >15min, esp. 50–90min. Avoid: less Floodmark tolerance than Bookends; poorly done → narrative interruption. See: Context Keeper (implementation of), Bookends (specialized Intermezzi wrapping whole talk), Backtracking (great return destination), Triad, Narrative Arc.
**Exuberant Title Top** (P) — Title starts center-screen (emphasis via lingering time), then migrates to normal top position before body reveals; gives print-normal density but presentation emphasis. How: place title at final top spot (print view stays clean); add build-in, then a move-before-build-in to center, then move-back-to-top; first body item builds after the return move (pushed-up effect). Tool reorders builds — manually put move above build-in. Avoid: slow reveal delays matching printout for follow-along audiences — explain early. See: Gradual Consistency (specialization of), Charred Trail (combine), Slideuments.
**Gradual Consistency** (P) — Build a slide intelligently over time toward its final (possibly printed) form; turns Slideuments' pre-printed no-surprise into narrative tension (what's missing/coming?). How: construct each slide's narrative in stages via animation — introduce concept, mutate it, add subcategories/examples, converge on print version; use click trigger for first item, build-after-previous for lesser items; add/remove elements to create interest. See: Slideuments, Exuberant Title Top (specific implementation), Soft Transitions.
**Charred Trail** (P) — Items appear one at a time; as each appears, previous grays out. Prints as complete slide but live only current point at full contrast — prevents reading ahead, printable, concise handout with talking points. How: PowerPoint — entrance animation (e.g. fade), set after-animation color to transparent version; set last element to "don't dim" or it costs an extra click. Keynote — any build-in + delivery "by highlighted bullet" (last element handled correctly). See: Context Keeper (form of, single-slide scope), Exuberant Title Top (combine), Slideuments.
**Soft Transitions** (P) — Subtle slide transitions (dissolve/fade) so you're not forced to expose exactly one slide of material at a time; unify a multi-slide thought. How: consistent subtle transition within a topic, strikingly different one to signal new topic (e.g. dissolve within, cube/push between); match transition to animation (both dissolve) to blur slide boundaries. See: Cookie Cutter (avoids), Intermezzi, Emergence, Gradual Consistency (multi-slide).
**Backtracking** (P) — Reestablish narrative context by purposefully duplicating slides; safely digress then return to where you left off (comedian's "callback"). How: copy the slide shown before the digression, paste at digression's end; distinctive transition to mark digression (e.g. cube right out, left back); no special tool support. Avoid: violates DRY — change every duplicate if you edit one; mark duplicates in speaker notes ("#\_#") and edit only the original. See: Context Keeper (implementation of), Intermezzi (great return destination).
**Invisibility** (P) — Elements absent from the printout but revealed live (opacity 0, surprise animations, blank slides); restores mystery/surprise when handouts spoil it, and forces focus back to presenter. How: Keynote — set opacity 0, action to 100%. PowerPoint "curtain trick" — borderless slide-sized shape over the surprise, exit-animate it (zero duration) to reveal. Avoid: erodes print consistency; easy to forget invisible elements at design time — mark in notes ("(-)"); use sparingly or it stops surprising. See: Slideuments (coping mechanism for).
**Crawling Credits** (P) — Closing-credits variant of Crawling Code: text slowly scrolls upward, oldest fading, giving each contributor/URL equal limited screen time when credits exceed one slide. How: single too-tall static image, bottom aligned to slide bottom, move-in animation bottom-to-top over a long duration; or mashup with Preroll technique. Avoid: embedded-movie version is hard to edit; slow readers miss items — follow with a static bookend of critical URLs. See: Crawling Code, Bookends, Preroll (symmetric opposite).
**Preroll** (P) — Advanced animated Bookends: auto-loops 2–3 opening slides while audience filters in; splits an overcrowded opening bookend into lower-density slides. How: two-file — separate deck with attention-grabbing transition (cube/fall), timed auto-advance, continuous loop. Embedded — screen-record that deck, trim, export to embeddable format (Keynote MOV/M4V, PowerPoint AVI/WMV), embed in first slide set to loop until advanced. Opening only — animation at close is worse than a static "done" signal. Avoid: extra files/tools, much more time-intensive than static Bookends. See: Bookends (implementation of), Crawling Credits (symmetric opposite).
**Infodeck** (P) — Document made with presentation tools, distributed and NEVER presented; consumed solo (screen, print, tablet) as discrete narrative elements, standalone like a spreadsheet. The form that works where Slideuments fails. How: apply normal book rules (esp. Creativity Patterns); use spatial layout/diagrams as primary elements; discourage long prose; DON'T use transitions/animations (time element deliberately dropped). Avoid: don't try to present it (dense, no time control); decide early — presentation vs Infodeck, never both; word-heavy + no time manipulation drifts toward antipattern. See: Slideuments (evil twin — people wanting Slideuments usually want this), Cookie Cutter, Narrative Arc.
**Slideuments** (AP) — One deck trying to be both live presentation aid AND attractive printed handout — incompatible vehicles; outcome worse than either alone, tool corrupts the message. Fix: prefer an Infodeck (captures the portable-info intent without the presentation compromise), or make a real document in a real tool. If forced: build a presentable deck + comprehensive speaker notes, distribute as PDF (not native), but note presentation tools are poor word processors and slides-as-outline drift toward Bullet-Riddled Corpse. Cope live via Gradual Consistency, Charred Trail, Exuberant Title Top, Invisibility, Soft Transitions, Coda. See: Infodeck, Bullet-Riddled Corpse, Cookie Cutter.
